# Akun dan penyimpanan privat — Phase 4.6

Catatan fase ini historis. Pembaruan skema 2, referensi transaksi dan langkah migrasi aman tercantum dalam [panduan Phase 4.7](PHASE4_7_STORAGE_MIGRATION.md).

Jalankan API dengan Node 24 dari folder aplikasi. `node:sqlite` bawaan menyimpan akun, keanggotaan, sesi, undangan, revisi pemeriksaan, foto sumber, dan chat pada `.data/accounts.sqlite`. Tidak ada layanan database tambahan. Variabel opsional `BUKTILAUT_ACCOUNT_DB_PATH` mengganti lokasi ini, misalnya untuk database uji terpisah. Jangan letakkan database di folder publik, sinkronkan ke repositori, atau masukkan ke ZIP aplikasi.

Skema pertama memakai `PRAGMA user_version=1`. Draf IndexedDB dan demo yang sudah ada tidak dimigrasikan otomatis. Pengguna memilih **Simpan ke arsip akun** untuk mengirim salinan. Foto disimpan sebagai BLOB privat; JSON revisi tidak berisi base64 foto. Detail dan foto hanya dilayani setelah pemeriksaan sesi dan keanggotaan ruang kerja di server. Rekaman audio mentah tidak disimpan; transkrip dan hasil tinjauan merupakan bagian pemeriksaan.

Setiap revisi arsip bersifat tetap. Identitas transaksi tetap sama saat disimpan ulang. `baseRevision` yang ketinggalan menghasilkan `409 REVISION_CONFLICT`; pengulangan kiriman identik dengan identitas dan revisi dasar yang sama mengembalikan revisi yang sudah tersimpan. Revisi draf baru tidak menghapus revisi terkonfirmasi sebelumnya. Ringkasan tanggal memakai revisi terkonfirmasi terbaru per transaksi, tanggal nota yang dikonfirmasi pengguna, serta WIB (`Asia/Jakarta`). Nilai belum diketahui tetap `null`, berbeda dari Rp0.

Kata sandi memakai scrypt dengan garam acak per akun. Token sesi acak hanya disimpan sebagai SHA-256 di database. Cookie `HttpOnly; SameSite=Lax` berlaku tujuh hari, ditambah `Secure` pada koneksi HTTPS langsung atau bila `BUKTILAUT_COOKIE_SECURE=true` (di belakang reverse proxy). Jalur perubahan memerlukan Origin yang diizinkan dan `X-BuktiLaut-Account: 1`. Header `X-BuktiLaut-Workspace` dapat mengikat permintaan ke ruang kerja asal agar kiriman tertunda tidak masuk ke ruang yang baru dipilih. Chat dipisahkan menurut pengguna, ruang kerja, dan konteks pemeriksaan.

Pemilik membuat ruang tim dan undangan untuk email tertentu. Kode/link disalin pengguna; aplikasi tidak mengirim email. Undangan berlaku 48 jam dan sekali pakai. Penerimaan memerlukan akun dengan email yang sama. Fase lokal ini belum memverifikasi kepemilikan email atau menyediakan pemulihan kata sandi. Jangan menyatakan konfigurasi lokal ini sebagai layanan produksi publik. Di belakang reverse proxy HTTPS, isi `BUKTILAUT_COOKIE_SECURE=true`. Server mendengarkan di loopback secara bawaan; untuk hosting atur `BUKTILAUT_HOST` dan `BUKTILAUT_ALLOWED_HOSTS`.

Untuk cadangan, hentikan API dengan bersih lalu salin database privat. Jika menyalin saat API masih aktif, gunakan cadangan SQLite yang konsisten; menyalin berkas utama saja dapat kehilangan transaksi di WAL. Jaga akses sistem operasi ke database dan cadangannya. Jangan memasukkan data akun, token sesi, atau kode undangan ke laporan uji/ZIP. Pembaruan skema berikutnya harus memakai migrasi eksplisit, tanpa menghapus database pengguna.

Uji ulang terpendek: buka dua sesi browser terpisah, daftar akun pertama dan simpan pemeriksaan bertanggal terkonfirmasi; masuk akun pertama pada sesi kedua dan buka foto, pasangan, penyesuaian serta laporan. Buat tim, undang akun kedua melalui kode, dan periksa akses anggota. Akun ketiga di luar tim harus ditolak saat memilih ruang/detail/foto tim. Simpan dari dua salinan revisi yang sama: salinan kedua harus mendapat konflik, bukan menimpa diam-diam. Tutup/buka chat, lalu pindah pemeriksaan dan ruang kerja untuk memastikan riwayat sesuai konteks.

## Bukti uji lokal

Skrip `work/phase46-accounts-browser.mjs` (arsip kerja tim, tidak disertakan di repo) memakai UI frontend `http://127.0.0.1:5177`, API lokal 8790, empat profil Chrome terpisah dan sumber sintetis. Pendaftaran, simpan eksplisit, buka ulang akun yang sama pada profil lain, kesamaan dua foto/baris/pasangan/penyesuaian 2 kg, laporan dan pembuatan PDF Rp490.000 lulus. Pembuatan tim serta penerimaan undangan dilakukan melalui UI. Anggota dapat membaca foto tim; akun di luar tim mendapat 403 untuk ruang, detail dan foto. Pemeriksaan CAS serta isolasi chat dilakukan melalui permintaan browser yang memakai cookie server nyata: pengulangan identik mengembalikan revisi 1; kiriman lama yang berbeda mendapat 409; revisi draf 2 mempertahankan ringkasan revisi terkonfirmasi 1. Riwayat akun lain tetap kosong dan kiriman dengan ruang asal yang tidak lagi aktif mendapat 409.

Bukti berada di arsip kerja tim (tidak disertakan di repo): `outputs/Phase4-6-accounts/checks.json`, `independent-session-report.png` dan `independent-session-report.pdf`. Screenshot laporan telah diperiksa. Ini uji browser desktop lokal dengan profil terpisah, belum bukti perangkat fisik lain atau deployment. Skrip ini tidak memanggil Vision, Voice atau provider berbayar. Pembuatan PDF teruji; rasterisasi PDF tersendiri belum dilakukan oleh pemilik penyimpanan.
